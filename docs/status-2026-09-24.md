## Session 1 — backend reusability for a non-Flutter VR client

Investigated whether the existing FastAPI/OCCT backend could support a
VR/XR companion app (Quest 2/3 standalone + PCVR) with a **non-Flutter**
headset client, reusing the backend as-is. Full write-up:
**`docs/vr-recon-2026-09-24.md`**. Five-point summary:

1. Every import/tessellate/export/solve endpoint is plain JSON-over-HTTPS
   with zero Flutter coupling — directly reusable by any HTTP client.
2. Per-part/per-assembly glTF is realistic and mostly additive: the
   `assembly-mesh` endpoint already computes deduplicated per-part geometry
   + per-instance world transforms; needs a new glTF encoder (sibling to
   `mesh_export.py::encode_glb`), not new geometry work.
3. The single-file native format is backend-owned/Flutter-independent; the
   **multi-file assembly composition protocol** (`external_ref` resolution)
   is entirely client-side today, by deliberate design (decision #6).
4. Biggest reimplementation risk: the **client-side 2D sketch solver**
   (`client/lib/sketch/local_solver/*`, a Dart/FFI port of the backend's
   `py-slvs` solver, built for drag responsiveness) — worse implications in
   3D VR than in 2D sketching. Assembly-graph composition/storage is second.
5. Multi-user shared assemblies are blocked on more than "stateless" —
   session identity conflates device with document, no persistence beyond
   client-held files, no concurrency/merge model, no per-user auth, no push
   channel. New backend infrastructure, explicitly out of scope originally.

## Session 2 — shared-network-storage design questions (this session)

Follow-up, scoped to designing a **shared-network-storage model for
multi-user assemblies**, with composition moved **server-side** and a
**non-Flutter Quest client**. Full write-up: **`docs/vr-recon-2-2026-09-24.md`**.
Five-point summary:

1. `assembly_graph_composer.dart`'s `external_ref` resolution (relative
   paths only, validated at write-time to reject absolute/`..` paths; DFS
   cycle detection via an explicit ancestor-path list, correctly
   distinguishing a real cycle from a supported diamond; stale-snapshot
   fallback via a local file cache) is a clean, low-risk port to Python —
   pure path/JSON graph traversal with no Dart-specific behavior. It
   actually gets *simpler* server-side: the Flutter-specific part
   (`StorageService`'s SAF/iOS-bookmark/desktop abstraction) disappears
   entirely in favor of a server process reading a real mounted filesystem.
2. File granularity: every `.didsa` file is one `Part`; assembly structure
   (`occurrences`/`mates`) lives entirely on the *referencing* file, never
   the referenced one (a child Part's file has no idea it's placed anywhere).
   Two users editing *different* files never collide. Two users editing the
   *same* file collide destructively — every save is a full-file overwrite,
   no field-level merge — so the natural safety unit is one-Part-per-file,
   and the cheap first step is per-file optimistic concurrency (an
   ETag/version check on write), not a real merge model.
3. Real measurement (built a 186-instance/4-unique-geometry bolted-flange-
   style assembly against a temporary local backend, not committed to the
   repo): `GET assembly-mesh` JSON = 470 KB / ~45 ms. The existing flattened
   `export/assembly-glb` = 1.33 MB / 573 ms (no instancing — duplicates full
   geometry per instance, confirmed via its own accessor counts: 18,432
   triangles emitted vs. 960 truly unique). A per-part **node-instanced**
   glTF (session 1's proposal) is estimated at ~90–100 KB from the same real
   geometry counts — ~5x smaller than the JSON endpoint, ~13–15x smaller
   than the current flattened export.
4. Plain HTTP over LAN is already fully supported by the backend (uvicorn
   never terminates TLS — Cloudflare Tunnel does that externally today; the
   Termux on-device deployment already runs the client and server over
   plain `http://127.0.0.1:8000`) and by the client's own HTTP code (no
   scheme validation). The real blocker is a **client-side Android manifest
   setting**: `network_security_config.xml` scopes `cleartextTrafficPermitted`
   to `127.0.0.1`/`localhost` only, blocking plain HTTP to any LAN IP by
   default under Android's `base-config`. Needs a deliberately-scoped
   cleartext exception (or a move to TLS with a bundled trust anchor) in
   whichever app runs on the Quest.
5. No existing roadmap item covers server-side composition or shared
   storage — the two closest hits in `docs/assembly-scope.md` (decisions #4
   and #6) state the *opposite* as "locked in." This work would need its own
   scoping doc (reopening those two decisions explicitly, not silently
   contradicting them), not a slot in an existing phase list.

  usable output. **Not retried this session** — session 2's own real-backend
  work (starting `uvicorn`, building a test assembly, timing endpoints) ran

  confirmed healthy; it's specifically the *full test suite's* wall-clock
  time that needs a longer budget (`run_in_background` + wait, not a fixed
  foreground timeout) next time a fresh pass/fail count is needed. Check the
  session-start hook's own pytest output first, as before.
- Real caveat on session 2's own measurements (not a product bug): the test
  assembly was built via STL import for speed, so its bodies' triangulation
  is fixed at import time and doesn't respond to the `quality` query
  param — confirmed identical payload size at `quality=0.0` vs `1.0` in this
  test. That's expected for imported/mesh-only geometry, not a backend
  defect, but it means this session's numbers don't demonstrate the quality
  slider's effect — a future measurement wanting that would need a fixture
  built from real parametric features (Extrude/Fillet/etc.), not imports.
- Nothing else newly found in the areas read this session; everything
  flagged in `docs/vr-recon-2-2026-09-24.md` (the whole-file-overwrite save
  model, the loopback-only Android cleartext scope, the absence of a
  shared-storage roadmap item) is existing, deliberate, documented design —
  called out for its relevance to this design question, not as a defect.
